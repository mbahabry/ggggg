# انتيفات بلس للنقليات — نظام إدارة الأسطول

نظام مركزي لإدارة أسطول شركة نقل بري: الشاحنات، السائقون، الرحلات، الصيانة، العملاء، والمالية — من لوحة تحكم واحدة بواجهة عربية RTL كاملة.

مبني كتطبيق ويب كامل قابل للتشغيل محليا: Next.js (App Router) + TypeScript + PostgreSQL عبر Prisma + مصادقة آمنة بالأدوار (RBAC) + بيانات تجريبية واقعية.

---

## التقنيات المستخدمة

| الطبقة | التقنية |
|---|---|
| الإطار | Next.js 16 (App Router, Turbopack, Server Actions) |
| اللغة | TypeScript |
| التنسيق | Tailwind CSS v4 + مكونات shadcn/ui (مبنية يدويا فوق Radix UI) |
| قاعدة البيانات | PostgreSQL 16 (عبر Docker) |
| ORM | Prisma 6 |
| المصادقة | NextAuth v5 (Credentials + JWT) |
| النماذج | React Hook Form + Zod |
| الرسوم البيانية | Recharts |
| الاختبارات | Vitest (اختبارات وحدة + اختبارات تكامل على قاعدة بيانات حقيقية) |

> **ملاحظة:** بيئة تشغيل هذه الجلسة كانت تمنع الوصول إلى `ui.shadcn.com`، لذلك تم بناء مكونات shadcn/ui يدويا (بنفس البنية والأسلوب الرسمي) فوق حزم `@radix-ui/*` المثبتة من npm مباشرة، بدلا من استخدام أداة `shadcn` CLI.

## التثبيت والتشغيل خطوة بخطوة

### المتطلبات

- Node.js 20.9 أو أحدث
- Docker و Docker Compose (لتشغيل PostgreSQL محليا)

### 1. تثبيت الحزم

```bash
npm install
```

### 2. إعداد متغيرات البيئة

```bash
cp .env.example .env
```

القيم الافتراضية في `.env.example` تعمل مباشرة مع `docker-compose.yml` بدون أي تعديل.

### 3. تشغيل قاعدة البيانات

```bash
docker compose up -d
```

سيشغّل هذا حاوية PostgreSQL 16 على المنفذ `5432` مع بيانات دائمة (volume).

### 4. تطبيق مخطط قاعدة البيانات (Migrations)

```bash
npx prisma migrate deploy
```

### 5. إدخال البيانات التجريبية (Seed)

```bash
npm run db:seed
```

سينشئ هذا: 5 مستخدمين تجريبيين (واحد لكل دور)، 80 شاحنة، 70 سائقا، 15 عميلا، 100 رحلة بحالات مختلفة، 20 سجل صيانة، 6 أشهر من البيانات المالية، وتنبيهات مستندات قريبة من الانتهاء أو منتهية.

### 6. تشغيل خادم التطوير

```bash
npm run dev
```

افتح المتصفح على [http://localhost:3000](http://localhost:3000) — سيتم توجيهك تلقائيا لصفحة تسجيل الدخول.

```
    prisma.ts                        # Prisma Client singleton

  auth.ts                     # إعداد NextAuth (Credentials + JWT + أدوار)

```

### فصل منطق الأعمال عن الواجهة

- **`lib/business/*`**: دوال منطق أعمال يمكن اختبارها بمعزل — قواعد انتقال حالة الرحلة، اكتشاف التأخر، حسابات مالية، وعمليات التعيين/التحويل التي تعمل على `Prisma.TransactionClient`.
- **`lib/actions/*`**: طبقة "Server Actions" رقيقة فقط: تتحقق من الجلسة والصلاحية، تتحقق من صحة المدخلات بـ Zod، تستدعي دوال `business/`، ثم تسجّل النشاط وتُحدّث المسارات (`revalidatePath`).
- **`lib/queries/*`**: استعلامات قراءة مخصصة لكل صفحة (تُبقي مكونات الصفحات نظيفة).

هذا الفصل هو ما يجعل اختبارات التكامل (`trip-service.test.ts`) ممكنة دون الحاجة لمحاكاة NextAuth أو Next.js Cache.

## القواعد الأساسية المطبَّقة

- **لا يمكن تعيين شاحنة** إلا إذا كانت حالتها "متاحة" (وليست تحت الصيانة/متوقفة/في رحلة) **ولا ترتبط برحلة نشطة أخرى** (فحص تعارض صريح، وليس فقط الحقل `status`).
- **لا يمكن تعيين سائق** إلا إذا كانت حالته "متاح" (وليس إجازة/موقوف/في رحلة) بنفس منطق فحص التعارض.
- عند بدء الرحلة فعليا (الانتقال إلى "في الطريق إلى التحميل") تتحول حالة السائق والشاحنة تلقائيا إلى "في رحلة"، ويُسجَّل وقت البدء الفعلي.
- عند اكتمال الرحلة ("تم التسليم") أو إلغائها، تعود حالة السائق والشاحنة تلقائيا إلى "متاح"، ويُسجَّل وقت الانتهاء الفعلي، وتُنشأ حركة إيراد مالية تلقائيا (مرتبطة بالرحلة، العميل، الشاحنة والسائق).
- **الرحلات المتأخرة تُكتشف تلقائيا** (وليست حالة تُضبط يدويا): أي رحلة لم تُسلَّم أو تُلغَ بعد وتجاوز موعد تسليمها المتوقع الوقت الحالي تُعرض ببطاقة "متأخرة".
- **سجل زمني كامل** لكل تغييرات حالة الرحلة (من → إلى، بواسطة من، وقت التغيير، ملاحظة).
- عند بدء الصيانة (تحت الفحص / جاري الإصلاح) تتحول حالة الشاحنة إلى "تحت الصيانة"، وعند الاكتمال تعود إلى "متاحة" ما لم تكن "متوقفة" مسبقا.
- **صلاحيات الأدوار (RBAC)** مطبَّقة على مستوى الصفحات (توجيه) وعلى مستوى كل Server Action (تحقق مستقل، وليس اعتمادا على واجهة المستخدم فقط).
- كل العمليات الحساسة (تعيين رحلة، تغيير حالة، إضافة مصروف، إغلاق طلب صيانة، تعديل مستخدم) تُنفَّذ داخل **معاملة قاعدة بيانات (Transaction)** وتُسجَّل في **سجل النشاط** مع القيمة السابقة والجديدة واسم المستخدم والوقت.
- المبالغ المالية مخزَّنة كـ `Decimal` في قاعدة البيانات (وليس `Float`) لتفادي أخطاء التقريب.
- تنبيهات انتهاء المستندات (رخصة، استمارة، تأمين، فحص دوري) تُصنَّف حسب الأيام المتبقية: **معلوماتية** (≤30 يوم) → **تحذيرية** (≤14 يوم) → **حرجة** (≤7 أيام أو منتهية فعلا).

## البيانات التجريبية (Seed)

- 80 شاحنة بأنواع وموديلات متنوعة، بعضها بمستندات منتهية أو قريبة الانتهاء عمدا لتجربة التنبيهات.
- 70 سائقا بجنسيات وحالات متنوعة (متاح، إجازة، موقوف)، بعضهم برخص قريبة الانتهاء.
- 15 عميلا بأسماء شركات سعودية واقعية (غير حقيقية).
- 100 رحلة موزعة على جميع الحالات (مسودة، بانتظار القبول، مقبولة، جارية بمراحلها، تم التسليم، ملغاة)، مع رحلات متأخرة عمدا.
- 20 سجل صيانة بحالات مختلفة.
- بيانات مالية واقعية لستة أشهر ماضية (إيرادات ومصروفات بعدة تصنيفات) تقارب الدخل الشهري المذكور (~3.2 مليون ريال).
- مدن سعودية حقيقية: الرياض، جدة، الدمام، بريدة، المدينة المنورة، مكة المكرمة، الجبيل، ينبع، الخبر، تبوك، حائل، أبها.

يمكن إعادة تشغيل السكربت في أي وقت لإعادة بناء البيانات من الصفر: `npm run db:seed` (يحذف البيانات الحالية بالكامل ويعيد إنشاءها).

## الميزات المنفَّذة

- تسجيل دخول آمن (Credentials + JWT) وخمسة أدوار صلاحيات كاملة.
- لوحة تحكم: بطاقات إحصائية، رسم بياني للإيرادات/المصروفات (6 أشهر)، رسم بياني لحالات الرحلات، أحدث الرحلات، تنبيه للمستندات القريبة من الانتهاء.
- إدارة الرحلات الكاملة: إنشاء، تفاصيل، سجل زمني، تحديث حالة، رفع إثبات تسليم، إلغاء.
- شاشة التخطيط والتوزيع: عرض الرحلات غير المعيَّنة، السائقين والشاحنات المتاحين، تعيين سريع بنافذة حوار مع فحص تعارض فوري، فلترة حسب المدينة.
- إدارة الشاحنات والسائقين والعملاء: بيانات كاملة، بحث، فلترة، ترقيم صفحات، صور، إحصائيات (عدد الرحلات، الإيرادات المحققة، الرصيد المستحق).
- الصيانة: بلاغات أعطال، تتبع حالة الطلب، ربط تلقائي بحالة الشاحنة، تسجيل تكلفة كمصروف مالي تلقائيا عند الاكتمال.
- المالية: تسجيل إيرادات/مصروفات، حالة السداد، تقارير حسب العميل/الشاحنة/السائق/الشهر.
- التنبيهات: توليد تلقائي (30/14/7 يوما) لجميع أنواع المستندات + رحلات متأخرة + صيانة + فواتير مستحقة، مع إمكانية التحديث اليدوي وتحديد "معالَج".
- سجل النشاط: تتبع كل عملية حساسة مع القيمة السابقة والجديدة.
- إدارة المستخدمين والصلاحيات (للمدير فقط): إضافة/تعديل/تفعيل/إيقاف حسابات، ربط حساب سائق بسجل سائق موجود.
- بوابة سائق مستقلة ومتجاوبة بالكامل: عرض الرحلات (بانتظار الموافقة، جارية، سجل)، قبول/رفض، تحديث حالة الرحلة خطوة بخطوة، رفع صورة إثبات التسليم، الإبلاغ عن عطل.
- وضع داكن/فاتح كامل، تصميم متجاوب (كمبيوتر وجوال)، جداول قابلة للبحث والفلترة والترقيم، حالات تحميل (Skeleton) وفراغ (Empty State) وأخطاء واضحة.
- اختبارات آلية (36 اختبارا) تغطي قواعد الأعمال الأساسية والصلاحيات.

## ميزات مقترحة للمرحلة التالية

- إشعارات فورية (WebSocket/Push) بدلا من التحديث اليدوي للتنبيهات.
- تتبع مواقع الشاحنات عبر GPS وخريطة تفاعلية للرحلات الجارية.
- تكامل مع بوابات دفع/فوترة إلكترونية سعودية (فاتورة، ZATCA) لإصدار فواتير ضريبية رسمية.
- تطبيق جوال أصلي لبوابة السائق (بدلا من الويب المتجاوب) مع إشعارات Push ووضع عمل بلا اتصال.
- تصدير التقارير إلى Excel/PDF.
- جدولة صيانة دورية تلقائية بناءً على قراءة العداد أو الزمن.
- سجل مخالفات مروري مفصل لكل سائق مع ربط بمصدر خارجي (ساهر).
- صلاحيات مخصصة على مستوى الحقل/الفرع بدلا من الأدوار الثابتة الخمسة فقط.

## ملاحظات تقنية إضافية

- **رفع الملفات** (صور الشاحنات، إثبات التسليم) يتم محليا عبر `/api/upload` ويُخزَّن في `public/uploads` — لا حاجة لأي خدمة سحابية مدفوعة لتشغيل النسخة التجريبية.
- **`proxy.ts`** هو الاسم الجديد لملف الـ Middleware في Next.js 16 (حل محل `middleware.ts`).
- تم بناء مكونات shadcn/ui يدويا لعدم توفر الوصول لـ `ui.shadcn.com` في بيئة التطوير — البنية والأسلوب مطابقان لمخرجات الأداة الرسمية.
